## Bewegungen (motions) — reine Lesevorgänge

Berechnen eine Linie, ohne das Papier zu berühren. Erst `mark`/`fold` wirken damit auf das Blatt ein (§4.10).

| Verb | Signatur | Was es tut |
| --- | --- | --- |
| `through` | `through .x .y` | Axiom ① — die eindeutige Linie durch zwei Punkte (§4.1). |
| `map … onto …` | `map .x onto .y` | Axiom ② — faltet `.x` auf `.y`: die Mittelsenkrechte der Strecke `x–y` (§4.2). |
| `perp … through …` | `perp --l through .p` | Axiom ③ — die Linie durch `.p`, senkrecht zu `--l` (§4.4). Hat nie einen geometrischen Fehlerfall. |
| `map … onto … perp …` | `map .p onto --l1 perp --l2` | Axiom ④ — projiziert `.p` auf `--l1`, parallel zu `--l2` (§4.5a). Bleibt in ℚ. |
| `map … onto …` (Linien) | `map --l1 onto --l2 [toward .p]` | Axiom ⑤ — Winkelhalbierende von `--l1` und `--l2`. Bei Schnitt ohne `toward`: Papier-Inzidenz-Filter wählt automatisch, wenn eindeutig; sonst ist `toward` Pflicht — es benennt eine **Richtung**, keinen Sektor (§4.5). Erste Operation, die ℚ verlässt (√). |
| `map … onto …` (Punkt auf Linie) | `map .p onto --d through .p' [toward .x]` | Axiom ⑥ — faltet `.p` auf `--d`, Kante fest durch `.p'`. Bis zu zwei Lösungen; `toward` ist hier **metrisch** (nächstgelegene Landung) (§4.5b). |
| `map … onto … and … onto …` | `map .p onto --d and .q onto --e [toward .x]` | Axiom ⑦ — die kubische Beloch-Faltung: `.p` auf `--d` *und* `.q` auf `--e`, eine Kante. Bis zu drei Lösungen, `toward` wählt metrisch (§4.5c). Erste Operation mit Kubikwurzeln. |

## Schreiboperationen (writes)

Verändern den Papierzustand und sind in Programmreihenfolge sequenziert (§4.10).

| Verb | Signatur | Was es tut |
| --- | --- | --- |
| `mark` | `mark <motion> [between .a .b \| at .p] [mountain] [#[...]]` | Ritzt die Linie, Blatt bleibt **flach**: unterteilt gekreuzte Lagen in Flaps, bewegt nichts. Emittiert FOLD `F` mit M/V-*Absicht* im Faltbild-Frame (§4.6). `--l = <motion>` bindet zusätzlich einen Namen. `between`/`at` klemmen die Ritzung auf ein Segment oder einen Referenzpunkt (seit v0.22-dev). |
| `fold` | `fold <motion> [moving <flap>] [up to <flap>] [mountain]` | Ritzt die Linie **und faltet sie**: unterteilt und bewegt Lagen. Emittiert FOLD `M`/`V` in beiden Frames. Ohne Bewegung (`fold --d ...`) faltet entlang einer bestehenden Kante (§4.6). |
| `collapse` | `collapse_item ("and" collapse_item)*` | Faltet mehrere bestehende Kanten, die einen Scheitelpunkt teilen, in einem Schritt zum flachen Endzustand — geprüft gegen Kawasaki/Maekawa/Stapelbarkeit (§4.9). Details: [collapse](/guide/collapse/). |
| `flip` | `flip` | Dreht das ganze Blatt um: jede Fläche invertiert ihre Ausrichtung, die Stapelreihenfolge kehrt sich um. Nachfolgendes Tal wird relativ zur ursprünglichen Vorderseite zu Berg (§4.7). |

## Operatoren und Selektoren — Lesevorgänge

| Ausdruck | Was es tut |
| --- | --- |
| `--l * --m` bzw. `.[--l --m]` | **Meet** — der Punkt, an dem sich die **materiellen Markierungen** zweier Kanten kreuzen. Braucht materielle (`mark`ierte) Operanden; ein reiner Wert (`--l = <motion>`, nie `mark`ed) hat keine Markierung zum Kreuzen (§4.3). |
| `--l & <constraint>` | **Filter** — projiziert das Kantenbündel `--l` auf das eine Segment, das zur Bedingung inzident ist (`.p`, `--a`, oder `#[...]`). An einer Singleton-Stelle Pflicht, sobald das Bündel mehr als ein Segment hat (§4.8). |
| `--l \ <constraint>` | **Negierter Filter** — behält die Segmente, die *nicht* durch die Bedingung laufen (§4.8). |
| `[--x --y]` | **Union** gleichtypisierter Bündel, z. B. `[--x --y] & .p` (§4.8). |
| `--[.a .b]` | **Join** — die reale Kante oder Papierkante durch zwei Punkte (nie eine erfundene „Sichtlinie“) (§4.10). |
| `#[.a .b …]` | **Flap-Selektor** — der eindeutige Flap, der alle genannten Punkte enthält; löst dieselbe Mehrdeutigkeit auf wie bei `moving` (§4.6, §4.8). |

## Modifikatoren

| Modifikator | Gehört zu | Bedeutung |
| --- | --- | --- |
| `moving <flap>` | `fold` | Der Anker-Flap: ein Punkt, eine Linie, oder `#[...]`. Bei Punkt-Faltungen aus dem bewegten Punkt implizit; bei Linienkonstruktionen (`through`, `perp`) und Faltungen entlang bestehender Kanten **Pflicht** (§4.6). |
| `up to <flap>` | `fold` | Beschränkt den Umfang auf den zusammenhängenden Lagenbereich vom Anker bis zum Ziel-Flap (inklusive), statt aller Lagen auf der Anker-Seite (§4.6). |
| `mountain` | `mark`, `fold`, `collapse`-Element | Kippt die Richtung vom Standard **Tal** auf **Berg** (§4.6, §4.9). |
| `toward .p` | Axiom ⑤/⑥/⑦ | Bedeutung variiert: bei Axiom ⑤ eine **Richtung** (die Zielseite der Faltung, §4.5); bei Axiom ⑥/⑦ eine **metrische** Nächste-Landung-Auswahl (§4.5b, §4.5c). |
| `.p over .q` | `collapse` | Legt Flap `.p` in der Endstapelung über `.q` — nur nötig, wenn mehr als eine gültige Stapelung übrig bleibt (§4.9). |
| `standing .r` | `collapse` | Verlangt, dass Flap `.r` aufrecht (nicht-flach) bleibt. Syntaktisch reserviert, der Evaluator lehnt es v1 grundsätzlich ab: „standing folds are not yet supported" (§4.9). |
