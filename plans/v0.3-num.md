# Beloch v0.3 — `Num`: exact constructible reals — Design

> **Status:** design, pending approval. The implementation plan (task
> breakdown) is appended by the writing-plans step. Design sections are the
> durable intent; tasks are disposable.

## Goal

A standalone module `lib/num.ml` providing **exact constructible real numbers** —
the smallest field containing ℚ and closed under square roots of non-negatives —
with a rational fast-path. This is the foundation the irrational axioms need;
**axiom 5** (the angle bisector, v0.4) is the first consumer, but `Num` is built
and tested entirely in isolation here, with no geometry or language change.

## Why a slice of its own

The angle bisector of two rational lines is generally irrational (e.g. lines
`y=0`, `y=x` → slope `√2−1`), so the geometry core must eventually move off `Q`.
The number type that replaces it is **not a small helper**: getting exact `sign`
to *terminate* requires a maintained canonical form, and that algebra deserves
isolated focus and an exhaustive test suite before any geometry depends on it.
Splitting it out keeps the hard, research-adjacent core behind a small stable
interface and lets v0.4 (migration + axiom 5) be mechanical on top.

## Math grounding (refs)

[hull2020] §3.2 Theorem 3.10: a number is an origami number iff it lies in a
**2-3 tower** `ℚ=F₀ ⊂ … ⊂ Fₙ` with each `[Fᵢ:Fᵢ₋₁] = 2 or 3`. Lemma 3.9 + proof
(`refs/hull2020.txt` ll. 2046–2052): the angle bisector (Hull's O4 = classic
**axiom 5**) and the other non-Beloch operations give an extension of **degree 2
or less**; only O7 (Beloch, axiom 6/7) reaches degree 3. So the numbers axiom 5
needs are exactly a **tower of quadratic extensions** = the constructible
numbers, and the tower is **nested** (`Fᵢ ⊂ Fᵢ₊₁`), so nested radicals like
`√(1+√2)` are genuine. `Num` therefore models the **full** quadratic tower; the
degree-3 (cube-root) part for axioms 6/7 is a later extension behind the same
interface.

## Representation

```
type t =
  | Rat of Q.t                     (* rational fast-path *)
  | Ext of t * t * t               (* Ext(a, b, d) = a + b·√d *)
```

**Canonical invariant** (maintained by every operation):

- in `Ext(a, b, d)`: `b ≠ 0`, `d` canonical with `sign d > 0`, and **`√d` is a
  strictly greater generator** (by a fixed total order, below) than every
  generator occurring in `a` or `b`.
- `Rat` is always canonical.

A **generator** is the radical `√d` of an `Ext`; generators are ordered by a
purely *syntactic* total order `compare_struct` on their radicands `d` (compare
`d` first, then `a`, then `b`; `Rat` < `Ext`). Any fixed total order works — its
only job is to give the ops a consistent "which generator is outermost" choice.

Note we do **not** require radicands to be square-free, nor do we merge
value-equal-but-syntactically-different generators (e.g. `√8` and `2√2` stay
distinct). That only costs representation size, never correctness — `sign`
decides value-equality regardless (`√8 − 2√2 → sign(8−8)=0`).

## The operations

**Smart constructor `ext a b d`** restores the `b≠0`/`d>0` part of the invariant:
if `sign b = 0` or `sign d = 0` return `a`, else `Ext(a,b,d)`.

**`add` / `mul` preserve canonicity** by always combining at the *maximal*
generator and recursing into coefficients (which carry strictly-smaller
generators):

- `Rat`⊕`Rat` → `Q` arithmetic.
- `Rat`⊕`Ext(a,b,d)` → fold the rational into `a`.
- `Ext(a₁,b₁,d₁)`⊕`Ext(a₂,b₂,d₂)`: let `c = compare_struct d₁ d₂`.
  - `c = 0` (same generator): combine like an extension polynomial —
    `add`: `ext (a₁+a₂) (b₁+b₂) d₁`;
    `mul`: `ext (a₁a₂ + b₁b₂·d) (a₁b₂ + a₂b₁) d`.
  - `c ≠ 0`: the larger-keyed `d` is outer; fold the whole smaller-keyed operand
    into the outer coefficient (`add`: into `a`; `mul`: distribute over `a` and
    `b`). The folded operand's generators are all `< d_outer`, so canonicity holds.

`neg` maps over the tree; `sub x y = add x (neg y)`.

**`sqrt x`** (of `sign x ≥ 0`): `ext zero one x` — i.e. `0 + 1·√x`, a fresh
generator above everything in `x`. (Rational fast-path: if `x = Rat q` and `q` is
a perfect rational square, return the exact rational root.)

**`inv` / `div`**: `inv (Ext(a,b,d)) = ext a (neg b) d · inv(a² − b²·d)` —
conjugate over the norm `a²−b²·d`, which lies in the field *below* `√d` (one
generator fewer), so `inv` recurses on a structurally simpler value;
`inv (Rat q) = Rat (1/q)` (`q ≠ 0`). `div x y = mul x (inv y)`.

**`sign` — the linchpin.** `sign (Rat q) = Q.sign q`. For `Ext(a,b,d)`
(`√d > 0`), with `sa = sign a`, `sb = sign b`:

- `sb = 0` → `sa`;
- `sa ≥ 0 ∧ sb > 0` → `+1`; `sa ≤ 0 ∧ sb < 0` → `−1`;
- opposite signs → compare magnitudes: `m = sign (a² − b²·d)`; result is `m` when
  `a > 0` (so `b√d < 0`), else `−m`.

`a² − b²·d` has its top generator strictly below `√d` (canonical invariant), so
**the tower height strictly decreases** and `sign` terminates. `compare x y =
sign (sub x y)`; `equal x y = (sign (sub x y) = 0)`.

**`to_float`** evaluates the tree numerically (`Q.to_float`, `sqrt`) — for output
only; never used in a decision.

The constructor and `sign`/`mul` are **mutually recursive** (`ext` calls `sign`;
`sign` calls `mul`/`sub`; `mul` calls `ext`); termination is by the tower-height
+ structural-size measure, not a single decreasing argument. This is the subtle
part — see Risk.

## Interface (the stable seam)

```
type t
val zero : t   val one : t
val of_int : int -> t   val of_q : Q.t -> t
val neg : t -> t
val add : t -> t -> t   val sub : t -> t -> t
val mul : t -> t -> t   val div : t -> t -> t   (* div: divisor sign ≠ 0 *)
val sqrt : t -> t                                (* arg sign ≥ 0 *)
val sign : t -> int      val compare : t -> t -> int   val equal : t -> t -> bool
val to_float : t -> float
```

Kept deliberately narrow so axioms 6/7 can later add the degree-3 (cube-root)
part of the 2-3 tower as a module-internal change without touching consumers.

## Testing (this slice is test-driven; the suite is the spec)

- **field axioms:** commutativity/associativity/distributivity on mixed
  rational+irrational values; `add`/`sub`/`mul`/`div`/`neg` round-trips
  (`x·inv x = 1`, `x − x = 0`).
- **`sqrt`:** `√2·√2 = 2` exactly; `√(rational square)` collapses to `Rat`;
  `sqrt` of a negative raises.
- **nested radicals:** build `√(1 + √2)`, square it back to `1 + √2`.
- **`sign` / `equal` — the core:** sign of mixed-sign sums (`√2 − 1 > 0`,
  `1 − √2 < 0`); equality of differently-written equal values (`√8 = 2√2`,
  `√(4·3) = 2√3`); a value that is exactly `0` written as `√2 − √2` and as
  `√8 − 2√2` → `sign = 0`; rational↔irrational compare (`1 < √2 < 3/2`).
- **termination guard:** a deliberately deep/nested construction (e.g. iterated
  `sqrt`/`add`) whose `sign` must still return — asserts the recursion bottoms
  out.
- **`to_float`:** within a tolerance of the numeric value (output only; the only
  place a float appears).

## Out of scope

Any geometry, language, or FOLD-output change (all in v0.4). Cube roots / the
degree-3 part of the tower (axioms 6/7). Performance optimization of deep nesting.
Canonicalizing value-equal generators (`√8` vs `2√2`).

## Risk

The only real risk is **termination/correctness of the mutually-recursive
`sign`/`mul`/`ext`** under the canonical invariant, plus **representation blowup**
on deep nesting (size/speed, never correctness — explicitly not optimized,
YAGNI). Both are contained to this one module and pinned down by the test suite
above, which is exactly why `Num` is its own isolated slice.

  **only** in `Num.to_float` (output/serialization helper), never in `sign`/`compare`/`equal`.
- New module is `lib/num.ml`; re-export it via `module Num = Num` in `lib/beloch.ml`

- **No `.mli`** — the project has none; expose the module's `let`s directly, matching
  the existing `lib/*.ml` style (inline type annotations, bare `Q.`/`Z.`).
- The canonical invariant (`Ext(a,b,d)`: `b≠0`, `sign d>0`, `√d` strictly greater

```ocaml
(** Exact constructible reals: a tower of quadratic extensions over ℚ.
    [t] is [Rat q] or [Ext (a, b, d)] meaning [a + b·√d] with [d > 0].
    Canonical invariant (held by routing all [Ext] building through [ext]):
    in [Ext (a, b, d)] the generator [√d] is strictly greater — by the purely
    syntactic order [compare_struct] — than every generator in [a] and [b].
    That invariant is what makes [sign] terminate (it recurses on [a²−b²d],
    which sits one extension below [√d]). Equality needs no canonical form:
    [equal x y] is [sign (sub x y) = 0]. Float appears only in [to_float]. *)

type t = Rat of Q.t | Ext of t * t * t

(* A total order on terms, used to choose the outer (maximal) generator and to
   recognise identical generators. Any fixed total order works. *)
let rec compare_struct (x : t) (y : t) : int =
  match x, y with
  | Rat a, Rat b -> Q.compare a b
  | Rat _, Ext _ -> -1
  | Ext _, Rat _ -> 1
  | Ext (a1, b1, d1), Ext (a2, b2, d2) ->
      let c = compare_struct d1 d2 in
      if c <> 0 then c
      else
        let c = compare_struct a1 a2 in
        if c <> 0 then c else compare_struct b1 b2

let rec neg (x : t) : t =
  match x with Rat a -> Rat (Q.neg a) | Ext (a, b, d) -> Ext (neg a, neg b, d)

let zero : t = Rat Q.zero
let one : t = Rat Q.one
let of_q (q : Q.t) : t = Rat q
let of_int (i : int) : t = Rat (Q.of_int i)

(* Mutually recursive core. [ext] keeps the b≠0 / d>0 part of the invariant;
   [add]/[mul] keep the generator-ordering part by always combining at the
   maximal generator and recursing into the (smaller-generator) coefficients. *)
let rec sign (x : t) : int =
  match x with
  | Rat q -> Q.sign q
  | Ext (a, b, d) ->
      let sa = sign a and sb = sign b and sd = sign d in
      if sb = 0 || sd = 0 then sa
      else if sa >= 0 && sb > 0 then 1
      else if sa <= 0 && sb < 0 then -1
      else
        (* a and b√d have opposite signs: compare magnitudes a² vs b²·d *)
        let m = sign (sub (mul a a) (mul (mul b b) d)) in
        if sa > 0 then m else -m

and ext (a : t) (b : t) (d : t) : t =
  if sign b = 0 || sign d = 0 then a else Ext (a, b, d)

and add (x : t) (y : t) : t =
  match x, y with
  | Rat a, Rat b -> Rat (Q.add a b)
  | Rat _, Ext (a, b, d) -> ext (add x a) b d
  | Ext (a, b, d), Rat _ -> ext (add a y) b d
  | Ext (a1, b1, d1), Ext (a2, b2, d2) ->
      let c = compare_struct d1 d2 in
      if c = 0 then ext (add a1 a2) (add b1 b2) d1
      else if c > 0 then ext (add a1 y) b1 d1
      else ext (add x a2) b2 d2

and sub (x : t) (y : t) : t = add x (neg y)

and mul (x : t) (y : t) : t =
  match x, y with
  | Rat a, Rat b -> Rat (Q.mul a b)
  | Rat _, Ext (a, b, d) -> ext (mul x a) (mul x b) d
  | Ext (a, b, d), Rat _ -> ext (mul a y) (mul b y) d
  | Ext (a1, b1, d1), Ext (a2, b2, d2) ->
      let c = compare_struct d1 d2 in
      if c = 0 then
        (* (a1+b1√d)(a2+b2√d) = (a1a2 + b1b2 d) + (a1b2 + a2b1)√d *)
        ext
          (add (mul a1 a2) (mul (mul b1 b2) d1))
          (add (mul a1 b2) (mul a2 b1))
          d1
      else if c > 0 then ext (mul a1 y) (mul b1 y) d1
      else ext (mul x a2) (mul x b2) d2

let compare (x : t) (y : t) : int = sign (sub x y)
let equal (x : t) (y : t) : bool = sign (sub x y) = 0

(* √x. Rational perfect squares collapse to [Rat]; otherwise a fresh generator
   [0 + 1·√x] strictly above everything in x. *)
let sqrt (x : t) : t =
  if sign x < 0 then invalid_arg "Num.sqrt: negative argument"
  else
    match x with
    | Rat q ->
        let num = Q.num q and den = Q.den q in
        let sn = Z.sqrt num and sd = Z.sqrt den in
        if Z.equal (Z.mul sn sn) num && Z.equal (Z.mul sd sd) den then
          Rat (Q.make sn sd)
        else ext zero one x
    | _ -> ext zero one x
```

```ocaml
(* 1/(a+b√d) = (a − b√d) / (a² − b²d); the norm a²−b²d lies one extension below
   √d, so [inv] recurses on a structurally simpler value. *)
let rec inv (x : t) : t =
  match x with
  | Rat q -> Rat (Q.inv q)
  | Ext (a, b, d) ->
      let norm = sub (mul a a) (mul (mul b b) d) in
      mul (ext a (neg b) d) (inv norm)

let div (x : t) (y : t) : t = mul x (inv y)

let rec to_float (x : t) : float =
  match x with
  | Rat q -> Q.to_float q
  | Ext (a, b, d) -> to_float a +. (to_float b *. Float.sqrt (to_float d))
```
