## Design (durable intent)

### What axiom 3 is

```
perp .p --l
```

The unique fold line through point `.p`, perpendicular to crease `--l`. In the
**classic Huzita-Justin numbering** this is **axiom 3** — operation ③ in
[justin1986] §8.1, `(P → P, D → D)`, "Perpendiculaire menée de P à D" — and it is
**Hull's O5** [hull2020] §1.5 ("fold line perpendicular to L passing through P").
Mind the numbering mismatch the spec already documents in §1: Hull's O-numbers
differ from the classic ones.

### Why this is the right next slice (numbering correction)

The journal (`notes/2026-06-28-3.md`) labelled "axiom 3" as *the angle bisector
(line onto line)*. **That label is wrong.** The authoritative classic table is
[justin1986] §8.1:

| # | Justin op | result | ℚ? |
|---|-----------|--------|-----|
| ① | (P→P, P'→P') | line through two points | rational |
| ② | (P→P') | perpendicular bisector | rational |
| **③** | **(P→P, D→D)** | **perpendicular through a point** | **rational** |
| ④ | (P→D, D'→D') | projection of P onto D parallel to D' | rational |
| **⑤** | **(D→D')** | **angle bisector** | **square roots** |
| ⑥ | (P→D, P'→P') | degree-2 equation | square roots |
| ⑦ | (P→D, P'→D') | degree-3 equation | cubic |

So: **classic axiom 3 = perpendicular through a point**, which is *rational*; the
**angle bisector is axiom 5**, which is where ℚ-closure first breaks (square
roots). That means [ADR 0008](../decisions/0008-exact-rational-arithmetic.md)'s
claim — closure breaks at axioms 5 and 6 — is **correct as written**; no
correction needed there. The slice that breaks ℚ (and forces the constructible-/
algebraic-number representation ADR 0008 defers) is axiom 5, not this one.

This plan therefore records the mislabel in `antipatterns.md` (matching the
repo's habit of pinning down such conflations — cf. the Hull/Caruana notes) and
sharpens the spec's numbering note, but introduces **no** number-representation
work: axiom 3 is fully rational.

### Geometry (exact ℚ)

Line `L: a·x + b·y = c`, point `P = (px, py)`. A line perpendicular to `L` has its
normal along `L`'s direction `(b, −a)`, giving the family `b·x − a·y = k`; fixing
it through `P`:

```
perpendicular_through(L, P) = { a' = L.b ;  b' = −L.a ;  c' = L.b·px − L.a·py }
```

All operations are in ℚ — no square roots, closure preserved.

### The P ∈ D subtlety (spec must state this explicitly)

[justin1986] §8.1 marks operation ③ with "Nombre = 1, 2": it has **two** valid
creases exactly when **P lies on D** — the perpendicular through P, *and* D
itself (a reflection maps line D onto itself either across a perpendicular or
across D itself; both pass through P only when P ∈ D). The second solution is the
**trivial identity-like one** — re-creasing the existing line D, yielding no new
geometry. Beloch always returns the **perpendicular**: it is unique and is the
meaningful construction. `perp` never errors. The spec §4 text must say this
explicitly — that two solutions exist, that we deliberately ignore the trivial
one, and that we assume the user wants the meaningful (perpendicular) variant.

### Surface syntax / grammar

`perp` is a **new leading keyword**, preserving "one keyword per axiom"
(`through` → axiom 1, `fold … to` → axiom 2, `perp` → axiom 3). Operands are
disambiguated by sigil: `.p` a point, `--l` a crease. This is the first axiom
production consuming a `crease_ref`.

```
axiom += "perp" point_ref crease_ref      ; axiom 3
```

### Output / provenance

`beloch:edges` gains `"axiom3"` as an `axiom` value; the `sources` list mixes a
point name and a crease name (`[".p"; "--l"]`) — no format change. No new FOLD
fields.

### Out of scope

Axiom 5 (angle bisector) and the constructible-/algebraic-number representation,
axiom 4 (projection), mountain/valley direction, the folded state.

(* axiom 3: the line through point p, perpendicular to line l. A line
   perpendicular to a·x+b·y=c has its normal along l's direction (b,−a), so it
   has the form b·x − a·y = k; fix k by passing through p. Exact over ℚ. *)
let perpendicular_through (l : line) (p : point) : line =
