# Beloch v0.4 — Axiom 5 (angle bisector) — Design

> **Status:** design, pending — **depends on v0.3 (`Num`)**. The implementation
> plan is appended by the writing-plans step. Design sections are the durable
> intent; tasks are disposable.

## Goal

Add **classic Huzita-Justin axiom 5** — the fold placing one line onto another
(the angle bisector) — as `bisect --l1 --l2 toward .p`. It is the first
**multi-solution** axiom and the first whose result leaves ℚ, so it migrates the
geometry core onto `Num` (built in v0.3) and adds a **disambiguation** selector.

The bisector is **axiom 5**, not axiom 3 — see
[antipatterns.md](../antipatterns.md) and the spec §1 numbering note. It is
Justin's operation ⑤ `(D → D')` [justin1986] §8.1, Hull's O4 [hull2020] §1.5
(verified `refs/justin1986.md` l. 126 "Bissectrices de D, D'";
`refs/hull2020.txt` l. 984 O4).

---

## 1. Dependency: `Num` (v0.3)

This slice assumes `lib/num.ml` — exact constructible reals (`Rat q | a+b√d`,
exact `sign`, ℚ fast-path) — is built, tested, and merged. See
[`v0.3-num.md`](v0.3-num.md). No number-representation work happens here; this
slice consumes the `Num` interface (`add/sub/mul/div/neg/sqrt/sign/compare/equal/
of_q/of_int/to_float`).

## 2. Geometry migration `Q → Num`

`geom.ml` (`point`, `line`, and every operation: `line_through`,
`perpendicular_bisector`, `perpendicular_through`, `parallel`, `intersection`,
`in_unit_square`, `seg_param`, `clip_to_unit_square`, `segment_intersection`,
`direction_half`, `ccw_compare`, `signed_area`), plus `state.ml` (vertex dedup),
`planarize.ml`, `faces.ml`, and `fold_emit.ml` (serialize via `Num.to_float`)
swap `Q.t` → `Num.t`. Axioms 1–4 produce only `Rat` values, so they stay exact,
fast, and **behaviourally unchanged**. The existing tests are the regression
gate: they must stay green through the migration (updated only where they
construct `Q` literals directly — now `Num.of_int`/`Num.of_q`).

## 3. Axiom 5 — the operation

`bisect --l1 --l2 toward .p`:

1. `O = intersection l1 l2`. If `None` (parallel) → the single midline (§3a). If
   `l1` and `l2` are the **same line** → error "lines are identical".
2. Otherwise two bisectors through `O`, directions `û1 ± û2` with
   `ûi = (ai, bi) / √(ai²+bi²)` — this is where the first `√` enters, producing
   `Num` line coefficients.
3. **Selection by `.p`** (§3b).

**3a. Parallel case.** The midline equidistant from both parallels (rational if
inputs are rational). `toward` is ignored if present.

**3b. Selection.** `l1` and `l2` cut the plane into four sectors (two pairs of
vertical angles); the two bisectors each run through one pair. `.p` lies in one
sector → that pair → its bisector. Exact test via `Num.sign` on the signed
distances of `.p` to `l1` and `l2`. **Precondition:** `.p` must not lie on `l1`
or `l2` (on a fold line the choice is ambiguous) → error "reference point on a
fold line; bisector ambiguous". With `toward` omitted and the lines intersecting
→ error "bisector is ambiguous; add `toward .p`".

## 4. Syntax / grammar

New keywords `bisect` and `toward`. `toward` is **optional**:

```
axiom += "bisect" crease_ref crease_ref [ "toward" point_ref ]      ; axiom 5
```

Two line operands with no connector (like `cross --d1 --d2`), then an optional
`toward .p` selector. `bisect` is result-named, matching `through` / `perp` /
`cross` (the majority pattern; only axiom 2's `fold … to` is action-named, and it
stays as-is — out of scope).

## 5. Errors

- `l1` and `l2` are the **same line** → "lines are identical".
- lines **intersect** and `toward` is **omitted** → "bisector is ambiguous; add `toward .p`".
- `.p` lies **on** `l1` or `l2` → "reference point on a fold line; bisector ambiguous".
- (existing) undefined crease/point names.

## 6. Output / provenance

`beloch:edges` axiom = `"axiom5"`; sources = the two crease names plus the point
name when present (`["--l1"; "--l2"; ".p"]`, or `["--l1"; "--l2"]` for the
parallel/no-`toward` case). No new FOLD field. Irrational coordinates render to
JSON decimal via `Num.to_float` (output only; internal values stay exact).

## 7. Tests + examples

- **bisector geometry unit:** l1 = x-axis, l2 = `y = x` → bisector slope
  `√2 − 1`, checked **exactly** as a `Num` (on-line test for the bisector through
  the origin).
- **two examples, identical configuration, `toward .a` vs `toward .b`** →
  visibly different creases (per the request — `examples/bisect-a.bel` and
  `examples/bisect-b.bel`, or one file with both, showing the selector's effect).
- **parallel example:** `bisect` of two parallel lines → the midline, no
  `toward`.
- **e2e:** FOLD output with `axiom5` provenance and correctly rounded irrational
  `vertices_coords`.
- **regression:** all prior tests green after the `Q → Num` migration.

## 8. Out of scope

`Num` itself (v0.3). Axiom 4 (projection), axioms 6/7 (cubic roots — would extend
`Num` to the degree-3 part of the 2-3 tower behind the same interface),
mountain/valley direction, the folded state.
