# 2026-06-28 (3) — v0.1 faces landed

`beloch fold` now emits `faces_vertices`. A folding viewer (e.g. Origami
Simulator) can **load** the crease pattern flat — it no longer rejects the file
for missing faces. It can't *fold* it yet (mountain/valley still deferred).

## What shipped

- Exact ℚ geometry helpers: `Geom.ccw_compare` (half-plane + cross-product, no
  `atan2`) and `Geom.signed_area` (shoelace).
- `planarize` reworked: boundary segments are now planarized uniformly with
  creases (boundary splits where a crease endpoint lands on it), and edges are
  deduped by `(min,max)` index — this also **resolved the v0.0 coincident-edge
  limitation**.
- `lib/faces.ml`: `Faces.extract` — bounded faces via exact half-edge traversal
  (CCW neighbour order, outer face dropped by negative signed area).
- `Fold_emit.to_json` takes the faces and emits `faces_vertices`; version bumped
  to `0.1.0-dev` (creator literal + `Beloch.version`).
- `examples/square.bel`; e2e: square → 1 face, diagonals → 4 triangles.
- 30 tests green; `nix build` (with doCheck) green.

Built via subagent-driven development: 5 TDD tasks, each reviewed.

## Next slice — axiom 3

Per the roadmap, **axiom 3** (`fold` line onto line — the angle bisector) is next.
It's the first axiom with *line* inputs, so it stretches the surface syntax
beyond point-only operands. Smaller than the layer model; good momentum before
the hard folded-state work. Mountain/valley (to make the simulator actually fold)
remains deferred and is the other strong candidate after axiom 3.

## Watch-point carried forward

When axioms 5/6 arrive, ℚ stops being closed (square/cubic roots) — the
constructible/algebraic number representation gets decided then.
