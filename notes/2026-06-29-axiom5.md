# 2026-06-29 — axiom 5 landed (v0.3-dev)

`bisect --l1 --l2 toward .p` is in: the angle bisector of two lines, parsed,
evaluated, and wired through the pipeline. First irrational coordinates in FOLD
output. Geometry core migrated from `Q` to exact constructible reals (`Num`).
Version bump to `0.3.0-dev`.

## What shipped

- `Geom.angle_bisectors : line -> line -> (line * line) option` — returns both
  bisectors for intersecting lines, or `None` for parallel lines.
- `Geom.parallel_midline : line -> line -> line` — the unique midline for the
  parallel case.
- `Ast.Bisect of crease_ref * crease_ref * point_ref option` — the new AST node.
- Lexer token `BISECT`, parser production
  `bisect crease_ref crease_ref [ toward point_ref ]`.
- Eval arm for `Bisect`: resolves names, dispatches on parallel/intersecting,
  applies the `toward .p` sector selector, emits provenance `"axiom5"`.
- Geometry core (`Geom`, `Point`, `Line`) migrated from `Q.t` to `Num.t`;
  existing tests serve as the regression gate — all green, no regressions.
- `examples/bisect.bel`; e2e: two configurations with `toward .a` / `toward .b`
  (different bisectors selected), plus parallel-midline case.

## Geometry core migration: Q → Num

`Num` (landed in the preceding slice, `notes/2026-06-29-num.md`) is a recursive
tower of quadratic extensions over ℚ: `Rat of Q.t` at the base,
`Ext(a, b, d)` = a + b√d above it. The geometry migration is a type-level
substitution — all `Q.t` scalars become `Num.t`. The existing tests serve as the
regression gate: if axioms 1–4 still pass, the migration is correct.

Axioms 1–4 produce no `Ext` nodes (ℚ is closed over all four), so there is no
runtime overhead for existing programs. The `Ext` constructor is introduced only
by `Geom.angle_bisectors`, which calls `Num.sqrt` on the line-normal
inner-product. The ℚ fast-path is intact.

## Reference-point selection and the parallel case

Two intersecting lines have two bisectors, perpendicular to each other. The
`toward .p` selector picks the bisector whose open angular sector contains `.p`.
If `.p` lies on one of the lines the sector test is degenerate (ambiguous) and
the evaluator raises an error.

Two parallel lines have exactly one midline; `toward` is ignored in that case
(and is optional in the syntax for this reason).

## First irrational coordinates

A program folding `y=0` and `y=x` produces a bisector with slope `√2 − 1` — a
`Num.Ext` value. This is the first time `to_float` in the FOLD serialiser has a
non-trivial value to convert. `vertices_coords` in the output is rounded at
serialisation; internal values remain exact.

## Watch-point: axiom-6/7 numbering

Before the axiom 6 or 7 slice, check the numbering against [[justin1986]] §8.1.
The cubic fold is Justin's operation ⑦ (the Beloch fold proper — fold two points
onto two lines simultaneously). Current project ADRs say "axiom 6" for the cubic;
if Justin's ⑥ is something else, the ADRs and spec will need a correction pass
before that code lands. The axiom-3/5 mislabel from `notes/2026-06-28-3.md` is
a proof that this is worth checking early.
