# Beloch v0.4 — Axiom 5 (angle bisector) — Design

> **Status:** design, pending — **depends on v0.3 (`Num`)**. The implementation
> plan is appended by the writing-plans step. Design sections are the durable
> intent; tasks are disposable.

## Goal

Add **classic Huzita-Justin axiom 5** — the fold placing one line onto another
(the angle bisector) — as `bisect --l1 --l2 toward .p`. It is the first
**multi-solution** axiom and the first whose result leaves ℚ, so it migrates the
geometry core onto `Num` (built in v0.3) and adds a **disambiguation** selector.

The bisector is **axiom 5**, not axiom 3 — see
[antipatterns.md](../antipatterns.md) and the spec §1 numbering note. It is
Justin's operation ⑤ `(D → D')` [justin1986] §8.1, Hull's O4 [hull2020] §1.5
(verified `refs/justin1986.md` l. 126 "Bissectrices de D, D'";
`refs/hull2020.txt` l. 984 O4).

---

## 1. Dependency: `Num` (v0.3)

This slice assumes `lib/num.ml` — exact constructible reals (`Rat q | a+b√d`,
exact `sign`, ℚ fast-path) — is built, tested, and merged. See
[`v0.3-num.md`](v0.3-num.md). No number-representation work happens here; this
slice consumes the `Num` interface (`add/sub/mul/div/neg/sqrt/sign/compare/equal/
of_q/of_int/to_float`).

## 2. Geometry migration `Q → Num`

`geom.ml` (`point`, `line`, and every operation: `line_through`,
`perpendicular_bisector`, `perpendicular_through`, `parallel`, `intersection`,
`in_unit_square`, `seg_param`, `clip_to_unit_square`, `segment_intersection`,
`direction_half`, `ccw_compare`, `signed_area`), plus `state.ml` (vertex dedup),
`planarize.ml`, `faces.ml`, and `fold_emit.ml` (serialize via `Num.to_float`)
swap `Q.t` → `Num.t`. Axioms 1–4 produce only `Rat` values, so they stay exact,
fast, and **behaviourally unchanged**. The existing tests are the regression
gate: they must stay green through the migration (updated only where they
construct `Q` literals directly — now `Num.of_int`/`Num.of_q`).

## 3. Axiom 5 — the operation

`bisect --l1 --l2 toward .p`:

1. `O = intersection l1 l2`. If `None` (parallel) → the single midline (§3a). If
   `l1` and `l2` are the **same line** → error "lines are identical".
2. Otherwise two bisectors through `O`, directions `û1 ± û2` with
   `ûi = (ai, bi) / √(ai²+bi²)` — this is where the first `√` enters, producing
   `Num` line coefficients.
3. **Selection by `.p`** (§3b).

**3a. Parallel case.** The midline equidistant from both parallels (rational if
inputs are rational). `toward` is ignored if present.

**3b. Selection.** `l1` and `l2` cut the plane into four sectors (two pairs of
vertical angles); the two bisectors each run through one pair. `.p` lies in one
sector → that pair → its bisector. Exact test via `Num.sign` on the signed
distances of `.p` to `l1` and `l2`. **Precondition:** `.p` must not lie on `l1`
or `l2` (on a fold line the choice is ambiguous) → error "reference point on a
fold line; bisector ambiguous". With `toward` omitted and the lines intersecting
→ error "bisector is ambiguous; add `toward .p`".

## 4. Syntax / grammar

New keywords `bisect` and `toward`. `toward` is **optional**:

```
axiom += "bisect" crease_ref crease_ref [ "toward" point_ref ]      ; axiom 5
```

Two line operands with no connector (like `cross --d1 --d2`), then an optional
`toward .p` selector. `bisect` is result-named, matching `through` / `perp` /
`cross` (the majority pattern; only axiom 2's `fold … to` is action-named, and it
stays as-is — out of scope).

## 5. Errors

- `l1` and `l2` are the **same line** → "lines are identical".
- lines **intersect** and `toward` is **omitted** → "bisector is ambiguous; add `toward .p`".
- `.p` lies **on** `l1` or `l2` → "reference point on a fold line; bisector ambiguous".
- (existing) undefined crease/point names.

## 6. Output / provenance

`beloch:edges` axiom = `"axiom5"`; sources = the two crease names plus the point
name when present (`["--l1"; "--l2"; ".p"]`, or `["--l1"; "--l2"]` for the
parallel/no-`toward` case). No new FOLD field. Irrational coordinates render to
JSON decimal via `Num.to_float` (output only; internal values stay exact).

## 7. Tests + examples

- **bisector geometry unit:** l1 = x-axis, l2 = `y = x` → bisector slope
  `√2 − 1`, checked **exactly** as a `Num` (on-line test for the bisector through
  the origin).
- **two examples, identical configuration, `toward .a` vs `toward .b`** →
  visibly different creases (per the request — `examples/bisect-a.bel` and
  `examples/bisect-b.bel`, or one file with both, showing the selector's effect).
- **parallel example:** `bisect` of two parallel lines → the midline, no
  `toward`.
- **e2e:** FOLD output with `axiom5` provenance and correctly rounded irrational
  `vertices_coords`.
- **regression:** all prior tests green after the `Q → Num` migration.

## 8. Out of scope

`Num` itself (v0.3). Axiom 4 (projection), axioms 6/7 (cubic roots — would extend
`Num` to the degree-3 part of the 2-3 tower behind the same interface),
mountain/valley direction, the folded state.

```ocaml
(** Exact constructible-real plane geometry. A line a*x + b*y = c with a,b,c in
    Num (the v0.3 constructible reals; rational on the fast-path). *)

type point = { x : Num.t; y : Num.t }
type line = { a : Num.t; b : Num.t; c : Num.t }

let point_equal (p : point) (q : point) : bool =
  Num.equal p.x q.x && Num.equal p.y q.y

let line_through (p : point) (q : point) : line =
  let a = Num.sub q.y p.y in
  let b = Num.sub p.x q.x in
  let c = Num.add (Num.mul a p.x) (Num.mul b p.y) in
  { a; b; c }

let perpendicular_bisector (p : point) (q : point) : line =
  let a = Num.sub q.x p.x in
  let b = Num.sub q.y p.y in
  let two = Num.of_int 2 in
  let mx = Num.div (Num.add p.x q.x) two in
  let my = Num.div (Num.add p.y q.y) two in
  let c = Num.add (Num.mul a mx) (Num.mul b my) in
  { a; b; c }

let perpendicular_through (l : line) (p : point) : line =
  let a = l.b and b = Num.neg l.a in
  let c = Num.add (Num.mul a p.x) (Num.mul b p.y) in
  { a; b; c }

let parallel (l1 : line) (l2 : line) : bool =
  Num.equal (Num.sub (Num.mul l1.a l2.b) (Num.mul l2.a l1.b)) Num.zero

let intersection (l1 : line) (l2 : line) : point option =
  let det = Num.sub (Num.mul l1.a l2.b) (Num.mul l2.a l1.b) in
  if Num.sign det = 0 then None
  else
    let x = Num.div (Num.sub (Num.mul l1.c l2.b) (Num.mul l2.c l1.b)) det in
    let y = Num.div (Num.sub (Num.mul l1.a l2.c) (Num.mul l2.a l1.c)) det in
    Some { x; y }

let in_unit_square (p : point) : bool =
  Num.sign p.x >= 0
  && Num.compare p.x Num.one <= 0
  && Num.sign p.y >= 0
  && Num.compare p.y Num.one <= 0

type segment = point * point

let seg_param ((p, q) : segment) (r : point) : Num.t =
  let dx = Num.sub q.x p.x and dy = Num.sub q.y p.y in
  let num = Num.add (Num.mul (Num.sub r.x p.x) dx) (Num.mul (Num.sub r.y p.y) dy) in
  let den = Num.add (Num.mul dx dx) (Num.mul dy dy) in
  Num.div num den

let clip_to_unit_square (l : line) : segment option =
  let z = Num.zero and o = Num.one in
  let cands = ref [] in
  let add p = if in_unit_square p then cands := p :: !cands in
  if Num.sign l.a <> 0 then begin
    add { x = Num.div l.c l.a; y = z };
    add { x = Num.div (Num.sub l.c l.b) l.a; y = o }
  end;
  if Num.sign l.b <> 0 then begin
    add { x = z; y = Num.div l.c l.b };
    add { x = o; y = Num.div (Num.sub l.c l.a) l.b }
  end;
  let uniq =
    List.fold_left
      (fun acc p -> if List.exists (point_equal p) acc then acc else p :: acc)
      [] !cands
  in
  match uniq with
  | p :: q :: _ when not (point_equal p q) -> Some (p, q)
  | _ -> None

let segment_intersection (s1 : segment) (s2 : segment) : point option =
  let (p1, q1) = s1 and (p2, q2) = s2 in
  match intersection (line_through p1 q1) (line_through p2 q2) with
  | None -> None
  | Some r ->
      let on s =
        let t = seg_param s r in
        Num.sign t >= 0 && Num.compare t Num.one <= 0
      in
      if on s1 && on s2 && in_unit_square r then Some r else None

let direction_half (dx : Num.t) (dy : Num.t) : int =
  if Num.sign dy > 0 || (Num.sign dy = 0 && Num.sign dx > 0) then 0 else 1

let ccw_compare ~(center : point) (a : point) (b : point) : int =
  let dax = Num.sub a.x center.x and day = Num.sub a.y center.y in
  let dbx = Num.sub b.x center.x and dby = Num.sub b.y center.y in
  let ha = direction_half dax day and hb = direction_half dbx dby in
  if ha <> hb then compare ha hb
  else
    let cross = Num.sub (Num.mul dax dby) (Num.mul dbx day) in
    let s = Num.sign cross in
    if s > 0 then -1 else if s < 0 then 1 else 0

let signed_area (pts : point array) : Num.t =
  let n = Array.length pts in
  let s = ref Num.zero in
  for i = 0 to n - 1 do
    let p = pts.(i) and q = pts.((i + 1) mod n) in
    s := Num.add !s (Num.sub (Num.mul p.x q.y) (Num.mul q.x p.y))
  done;
  Num.div !s (Num.of_int 2)
```

```ocaml
(* axiom 5: the two angle bisectors of l1, l2 (None if parallel). With
   ni = √(ai²+bi²), points equidistant satisfy n2·L1 = ±n1·L2, giving lines
     (n2 a1 ∓ n1 a2) x + (n2 b1 ∓ n1 b2) y = n2 c1 ∓ n1 c2.
   bis_eq is the d1=d2 bisector (minus); bis_opp the d1=−d2 bisector (plus). *)
let angle_bisectors (l1 : line) (l2 : line) : (line * line) option =
  let det = Num.sub (Num.mul l1.a l2.b) (Num.mul l2.a l1.b) in
  if Num.sign det = 0 then None
  else
    let n1 = Num.sqrt (Num.add (Num.mul l1.a l1.a) (Num.mul l1.b l1.b)) in
    let n2 = Num.sqrt (Num.add (Num.mul l2.a l2.a) (Num.mul l2.b l2.b)) in
    let mk add_sign =
      let comb u v = if add_sign then Num.add u v else Num.sub u v in
      { a = comb (Num.mul n2 l1.a) (Num.mul n1 l2.a);
        b = comb (Num.mul n2 l1.b) (Num.mul n1 l2.b);
        c = comb (Num.mul n2 l1.c) (Num.mul n1 l2.c) }
    in
    Some (mk false, mk true)

(* midline of two parallel lines: rescale l2 to l1's normal, average offsets. *)
let parallel_midline (l1 : line) (l2 : line) : line =
  let k = if Num.sign l1.a <> 0 then Num.div l2.a l1.a else Num.div l2.b l1.b in
  let c = Num.div (Num.add l1.c (Num.div l2.c k)) (Num.of_int 2) in
  { a = l1.a; b = l1.b; c }
```

    | Ast.Bisect (c1, c2, p_opt) ->
        let l1 = lookup_crease c1 and l2 = lookup_crease c2 in
        let base = [ "--" ^ c1.cname; "--" ^ c2.cname ] in
        let eval_at (l : Geom.line) (pt : Geom.point) : Num.t =
          Num.sub
            (Num.add (Num.mul l.Geom.a pt.Geom.x) (Num.mul l.Geom.b pt.Geom.y))
            l.Geom.c
        in
        (match Geom.angle_bisectors l1 l2 with
         | None ->
             (* parallel: identical line -> error, else the midline *)
             let k =
               if Num.sign l1.Geom.a <> 0 then Num.div l2.Geom.a l1.Geom.a
               else Num.div l2.Geom.b l1.Geom.b
             in
             if Num.equal l2.Geom.c (Num.mul k l1.Geom.c) then
               Error.fail span "lines are identical";
             (Geom.parallel_midline l1 l2, "axiom5", base)
         | Some (bis_eq, bis_opp) ->
             (match p_opt with
              | None -> Error.fail span "bisector is ambiguous; add `toward .p`"
              | Some pr ->
                  let p = lookup_point pr in
                  let s1 = Num.sign (eval_at l1 p)
                  and s2 = Num.sign (eval_at l2 p) in
                  if s1 = 0 || s2 = 0 then
                    Error.fail span "reference point on a fold line; bisector ambiguous";
                  let bis = if s1 = s2 then bis_eq else bis_opp in
                  (bis, "axiom5", base @ [ "." ^ pr.name ])))

### 4.5 Axiom 5 — fold one line onto another *(since v0.3-dev)*

​```
bisect --l1 --l2 toward .p
​```

The fold placing line `--l1` onto line `--l2`: the **angle bisector**
[[justin1986]](#ref-justin1986) §8.1 (operation ⑤), [[hull2020]](#ref-hull2020)
§1.5 (O4 in Hull's numbering; see §1). Two intersecting lines have **two**
bisectors (perpendicular to each other); the optional `toward .p` selector picks
the one whose angular sector contains `.p`. Two **parallel** lines have a single
**midline**, and `toward` is ignored.

**Errors:** the two lines are the **same line**; the lines intersect and
`toward` is **omitted** (ambiguous); `.p` lies **on** `--l1` or `--l2`
(ambiguous).

This is the first axiom whose result leaves ℚ — the bisector of two rational
lines is generally irrational (slope `√2−1` for `y=0` and `y=x`). All geometry is
now computed over exact **constructible reals** (`Num`; see
[ADR 0010](../decisions/0010-constructible-real-numbers.md) and §6), so equality,
parallelism, and on-paper tests stay exact.
